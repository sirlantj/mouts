# dotnet-review

When reviewing code:

1. Analyze SOLID violations.
2. Identify performance bottlenecks.
3. Evaluate Big O complexity.
4. Check Clean Architecture boundaries.
5. Verify dependency injection usage.
6. Identify thread safety issues.
7. Review async/await usage.
8. Suggest refactoring opportunities.
9. Check testability.
10. Provide a severity level for each issue.
11. Follow clean code principles. DRY, KISS, YAGNI.
12. Check for security vulnerabilities, OWASP (e.g., SQL injection, XSS).
13. Always explain trade-offs and provide improved code examples.
14. Consider maintainability and readability in recommendations.
15. Evaluate adherence to .NET best practices and coding standards.

Output format:

- Issue
- Impact
- Recommendation
- Example Fix
